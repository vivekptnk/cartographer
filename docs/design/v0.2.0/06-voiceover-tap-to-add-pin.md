# 06 — VoiceOver Script: Tap-to-Add-Pin (Golden Path)

**Scope:** The full VoiceOver script for the golden-path user flow — a user with VoiceOver enabled opens the app, drops their first pin, edits its title, and saves. Every utterance, every focus target, every hint. This script is the **approval artifact** required by [CHA-139](/CHA/issues/CHA-139) exit criteria.

**Status:** Draft — pending approval by [CTO – Cartographer](/CHA/agents/cto-cartographer).

**Related:** [01 Map Interactions](./01-map-interactions.md), [02 Annotation Sheet](./02-annotation-sheet.md), [03 Empty States §2](./03-empty-states.md#2-state-a--first-run-empty-project).

---

## 1. Prerequisites

- Device: iPhone with iOS 17+, VoiceOver **on** (Settings → Accessibility → VoiceOver → On).
- App: CartographerDemo, first launch on this device.
- Project: default project exists, zero annotations.
- Network: online or offline — behavior is identical on the golden path. (Offline shows the offline indicator but that is orthogonal.)

---

## 2. Script

### 2.1 App launch

**VoiceOver focus lands on:** the navigation bar title.

**Utterance:**
> *"Default Project. Heading. Back. Button."*

(VoiceOver reads nav title + the back-button trait even if no back navigation is possible. Standard iOS behavior.)

**User swipes right** — focus moves to the **Offline indicator** in the nav bar trailing area.

**Utterance:**
> *"Live. Button. Double-tap for details."*

(See [04 §7 VoiceOver](./04-offline-indicator.md#7-accessibility).)

**User swipes right again** — focus enters the **map canvas**.

**Utterance:**
> *"Map. Adjustable. Default Project, showing zero annotations. Pan with two fingers. Use the rotor to find annotations."*

---

### 2.2 First-run empty-state card

Because the project is empty and `hasSeenOnboarding == false`, the first-run card is modal overlaid on the map (see [03 §2](./03-empty-states.md#2-state-a--first-run-empty-project)).

**VoiceOver announces on appearance:**
> *"Alert. Your map is empty. Tap the pin icon below to drop your first annotation anywhere on the map."*

(Delivered via `UIAccessibility.post(notification: .screenChanged, argument: firstRunCard)` — focus auto-moves to the card's title.)

**User swipes right** — focus moves to the primary CTA.

**Utterance:**
> *"Show me how to add a pin. Button. Enters pin-drop mode. You'll be asked to tap a location on the map."*

**User double-taps** — the card dismisses, drop-pin mode activates, the mode indicator pill at the top of the map announces itself.

**VoiceOver announcement (not focus-moving):**
> *"Pin-drop mode. Tap anywhere on the map to drop your first pin."*

(Posted via `.announcement` notification; focus remains on the map.)

---

### 2.3 Focus returns to the map

Focus auto-returns to the map view.

**Utterance (re-focus):**
> *"Map. Adjustable. Default Project, showing zero annotations. In pin-drop mode. Double-tap the map to drop a pin at the center."*

**Rationale.** VoiceOver users cannot "tap to drop" by sighted tap location — they tap-to-activate wherever their focus is. So when in drop-pin mode, double-tapping on the map view **drops a pin at the map's visual center** (via `MKMapView.region.center`). This is the documented accessibility behavior — an explicit, well-known alternative to sighted interaction. We announce it in the focus label.

---

### 2.4 User double-taps the map

**System behavior:**
1. `AnnotationEngine.insertPin(at: mapView.region.center)` fires.
2. Medium haptic.
3. New pin renders with a fade-in (Reduce Motion honored).
4. Annotation sheet opens in edit-mode at `.medium` detent, title field first-responder.
5. Keyboard appears; sheet auto-promotes to `.large` detent.

**VoiceOver announcement (sheet appearance):**
> *"Sheet. New Pin. Dismiss from top."*

(System-generated by `UISheetPresentationController` with modal a11y.)

**Focus auto-moves to:** the title field.

**Utterance:**
> *"Name this Pin. Text field. Required. Edit text. Double-tap to edit. Using keyboard."*

(Standard `UITextField` with placeholder + `accessibilityLabel = "Pin title"` + VoiceOver's built-in keyboard announcement because it's already the first responder.)

---

### 2.5 User types a title

User types via the keyboard (or via VoiceOver's Braille input, dictation, or onscreen keyboard letter-by-letter).

**Per-keystroke utterance** (VoiceOver speaks each character — system behavior; we do not override).

After the user types `"Summit cairn"`:

**VoiceOver utterance (if user lifts finger off keyboard):**
> *"Summit cairn. Text field."*

---

### 2.6 User swipes to the Save button

**Focus moves to:** the Save button in the sheet toolbar.

**Utterance:**
> *"Save. Button."*

(No extra hint in edit-mode — action is self-evident. `accessibilityLabel = "Save"`.)

**User double-taps** — Save fires.

**System behavior:**
1. `AnnotationEngine.updateTitle(id:, to: "Summit cairn")` → op-log append.
2. Save button shows `ProgressView()` briefly (< 50ms typical).
3. Sheet dismisses.
4. Focus returns to the map.

**VoiceOver announcement on sheet dismiss:**
> *"Sheet dismissed. Back on map."*

(Via `.announcement` notification.)

---

### 2.7 Focus returns to the map, now with one annotation

**Focus lands on:** the map view. Because a new annotation is now present near the center, the map's default a11y label updates.

**Utterance:**
> *"Map. Adjustable. Default Project, showing one annotation. Use the rotor to find annotations."*

---

### 2.8 User uses the rotor to find the new pin

User rotates two fingers on the screen to open the VoiceOver rotor, swipes down to select `"Annotations"`, then swipes up/down to cycle.

**Utterance for the first rotor item:**
> *"Pin. Summit cairn. Located at the center of the map. Button."*

(`accessibilityLabel = "Pin"`, `accessibilityValue = "Summit cairn"`, `accessibilityHint` defaults to button trait context. "Located at the center of the map" is a positional clue posted when the rotor lands on the annotation. We compute this via the annotation's position relative to `mapView.region.center`:
- Within 20% of viewport: "center of the map"
- Beyond: "upper-left", "lower-right", etc. (eight compass directions)
- Off-screen: "off-screen, upper-left" etc.

This is the clearest spatial summary VoiceOver can give without coordinate-reading, which is slow and unintuitive.)

**User double-taps on the rotor item** — focuses on the annotation view itself (but does NOT open the sheet; VoiceOver conventions: swipe-up/down for actions, double-tap for default action).

**Utterance on focus:**
> *"Pin. Summit cairn. Button. Double-tap to open details. Actions available. Located at the center of the map."*

**User double-taps** — sheet opens in **read-mode**.

---

### 2.9 Sheet in read-mode

**VoiceOver announcement:**
> *"Sheet. Pin details."*

**Focus auto-moves to:** the title text (read-mode uses text, not field).

**Utterance:**
> *"Summit cairn. Heading."*

**User swipes right** — focus moves to the coordinate row.

**Utterance:**
> *"Coordinate, 37 point 77 degrees North, 122 point 42 degrees West. Actions available."*

(VoiceOver magic-tap + swipe-up opens actions; the only custom action here is "Copy.")

**User continues swiping right** — reaches the Edit button.

**Utterance:**
> *"Edit. Button."*

Then Delete button.

**Utterance:**
> *"Delete. Button. Permanently removes this pin. Activates a confirmation."*

User dismisses the sheet by two-finger-scrub (the VoiceOver gesture for Escape).

**VoiceOver announcement:**
> *"Sheet dismissed. Back on map."*

## 3. Script summary — utterance count

| Step | Approximate utterance count |
|---|---|
| 2.1 Launch | 3 |
| 2.2 First-run card | 3 (announcement + title + CTA) |
| 2.3 Focus returns to map, pin-drop mode | 1 announcement + 1 focus label |
| 2.4 Sheet appears, title focused | 2 |
| 2.5 Typing | per-character + post-type |
| 2.6 Save | 2 |
| 2.7 Map with annotation | 1 |
| 2.8 Rotor navigation | 2 per cycled item |
| 2.9 Sheet read-mode | 4+ |
| **Total (golden path)** | ~18 user-initiated utterances + per-keystroke typing |

Short. Deliberate. No redundant phrasing.

## 4. Design principles applied

- **Announcements over focus stealing.** We use `.announcement` for ambient state changes (mode enter, sheet dismiss) and `.screenChanged` only when a new modal surface appears. This avoids yanking the user's navigation context.
- **Spatial language.** Coordinates are read in degrees with compass direction, not decimals, because `"37.7749, -122.4194"` is unintelligible to most users. Positional clues ("upper-left", "off-screen") carry the spatial understanding.
- **No extra verbosity in focus labels.** Each label is the shortest form that uniquely identifies + hints at an action. Additional context comes from hints, not labels.
- **Button traits always explicit.** Every interactive element carries `.button` (or `.header`, `.link`) so VoiceOver users always know "what kind of thing" they're on.
- **Custom actions over multiple buttons.** Copy-coordinate is a VoiceOver action, not a tappable icon. Less clutter, same power.
- **Rotor for spatial scan.** The custom `"Annotations"` rotor is how VoiceOver users browse the map — we cannot expect them to pan-and-inspect. Rotor order = distance-from-viewport-center ascending.
- **Equivalent-power parity.** VoiceOver users can do everything the golden-path sighted user can do: drop a pin, title it, save, find it, delete it. No capability gap.

---

## 5. Known tradeoffs / deviations from stock iOS

- **Double-tap drops at map center, not at focus location.** Standard UIKit double-tap activates the focused element; the "focused element" here is the whole map. Activating the map in drop-pin mode means "drop at the logical center." This is an explicit deviation from sighted behavior where tap location matters — we compensate with a clear focus-label ("double-tap to drop a pin at the center"). Alternatives considered:
  - **Long-press on map in drop-pin mode to drop at the rotor-selected coordinate:** rejected — introduces a gesture VoiceOver users don't have a natural analog for.
  - **A separate "Drop pin here" button in the toolbar:** viable; defer as a future enhancement if user feedback requests it. For v0.2.0, center-drop is intentional, documented, and matches how Apple Maps handles tap-to-drop under VoiceOver.
- **Rotor positional labels.** "Upper-left" etc. require computing screen position each time the rotor updates. Minor work for the iOS Engineer but well worth the usability gain. If performance becomes an issue with 10k annotations, cache the position at rotor-build time and invalidate on `regionDidChangeAnimated`.

## 7. Open questions for CTO

- **Dictation vs. keyboard for title entry.** The script describes keyboard input. VoiceOver users frequently use dictation. No behavioral difference — both end at the same text field. No change required, just noting.
- **Announcement on pin-drop success.** Currently we rely on sheet appearance for feedback. Alternative: post an announcement like *"Pin dropped."* before the sheet opens. I recommend **against** — the sheet appearance (with the pin already in the op-log) is sufficient signal and an extra announcement adds chatter. Confirm.
- **Rotor category naming.** `"Annotations"` vs. `"Pins, Routes, and Polygons"`. I chose the generic term for brevity. Confirm.
